# FS01 预注册比较 v1 — 2026-09-07

在研究结果产生前冻结。目的：检验完整方法流程与检索能力，不能由链接数量推导胜负。

## 样本与条件

- T1 开发题：Windows 本地 Python 服务需要监听本地 NTFS 和 SMB 共享目录，可靠发现文件写入完成，比较 watchfiles、watchdog 及轮询方案。要求给可执行选择、失败条件、原作者/维护者证据，不能把文件变化事件当写入完成。无管理员权限、无新增收费服务。纯研究，不修改实际服务。
- T2 近期社区题：最近30天开发者将 SQLite WAL 用于多进程服务有哪些实际故障与可执行规避；区分历史背景和近期证据。运行 last30days 原完整 keyless 工作流，再与 field-search 相同题目与可用权限比较。单次当前样本，不推导全平台覆盖。
- H1 留出题（改进冻结前禁止搜索）：Python 服务导入用户提供的 ZIP 压缩包，Windows 环境，比较标准库与第三方成熟方案；需处理路径越界、符号链接、解压炸弹和嵌套压缩包，给最小可行选择与边界。与 T1 不同任务，不用它调参。留出题失败可修复，但须明确失去留出属性并新增 H2。

## 公平性

T1 research-skill 原方法与 field-search-v3 分别在零历史上下文子代理中运行；同一继承模型、相同工具权限、每臂最多 12 次搜索请求（每请求最多3查询）及12次原文读取请求、约8分钟有效研究上限（工具阻塞单列）。不互看答案。research-skill要求的特定Opus不在本宿主可选模型中，因此为同宿主方法移植复现，不能声称原作者模型复现。其取回→调查→反对意见→综合→存储→再次取回全部执行。宿主规则优先于远程格式规则。研究知识仅保存本隔离实验内。

T2 last30days原程序不含自有LLM综合时，由同宿主执行读取与综合，记录keyless模式受限平台；自动排序程序耗时另列。不得把单采集器输出当完整Skill。

所有运行记录真实开始/结束时间、上游提交、命令、来源读取证据、调用条件和费用可见性。宿主订阅消耗不可准确按次货币计费，标未知；不得写零成本。外部付费API未授权。

## 验收判断（逐条件，无加权平均）

1. 决定性事实找到且原文读到；snippet不算。
2. 主张有适用条件、原始依据，区分实测和文档。
3. 最强反例/成熟替代未遗漏，不把多镜像作独立证据。
4. 建议能行动且边界正确；关键错误一票否决该任务持平。
5. 时间和访问差异公开；不通过字数/来源数量/自评分宣布胜出。

第一次比较用于发现差距；修改后同题回归仅说明修复，H1及必要H2用于独立验证。独立验收读取产物和关键原文，不参与实现。不要求为了超过而制造改动；保留有用原工具按需调用也可满足复用目标。超越只按已证实的具体能力表述，未部署/未完整运行者一律不参与优势主张。
