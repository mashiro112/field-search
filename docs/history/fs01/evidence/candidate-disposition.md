## Supersearch execution details

candidate-supersearch-run.mjs calls upstream exported install({codexHome: isolatedPath}); it never sets global CODEX_HOME. Direct `node scripts/install.mjs` on Windows can silently do nothing because upstream compares import.meta.url with `file://${process.argv[1]}`. Calling the exported function provides the documented same installation semantics and produced all 10 junctions. The same Windows entry guard affects dedicated search files; candidate-supersearch-probe.mjs imports the actual exported search functions instead. No upstream source changed.

The first test runner found 56 Node tests passing but failed to discover Python because `python` on the initial PATH was the WindowsApps stub. With bundled Python directory in a clean child PATH, the complete original runner exits 0 including WeChat unittest tests; logs and argv are in candidate-supersearch-execution.json. The source modules all explicitly report XAI_API_KEY is required under the clean keyless environment. Missing-key retries were not repeated since they cannot alter the authorization/dependency state.

The WeChat collector successfully returned 5 actual titles/account/date/original links in 2.406 s: one was a 2026-09-02 WAL-reset retelling, the others were older SQLite background. These are discovery results only: none was promoted to primary evidence without original reading. Native Web + WeChat is deployable now; this does not replicate eight dedicated paid/login source lanes.
