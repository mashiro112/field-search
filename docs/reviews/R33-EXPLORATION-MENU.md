# R33: capability choices before implementation

Date: 2026-10-03. Status: **research menu; awaiting the owner's branch selection**. Inspected baseline: `d3b00fab00a9c9da97171797e77502559bfe713c`, installed Skill and selected `search.py`, `locate.py`, `video.py` contracts. The remote and publication checkout matched and were clean at the start. No FS source, dependency, login, research job or background service was changed. Source manifest remains 185 files. Current operational acceptance is still [R32](R32-RESULTS.md).

The owner wants broad exploration, then personal selection before deep investigation or execution. Candidates are grouped by what the user gains, not by a mandatory tool stack. Cost labels below are engineering estimates of setup and maintenance, not measured token savings. Official/API capabilities, an installed host connector, and a locally accepted FS route remain separate facts.

1. **Find readable papers and attachments.** Resolve a title/DOI, distinguish versions and locate an accessible copy plus relevant supplements. Reuse the host's existing Scholar/OpenAlex tools before adding another basic search adapter; [OpenAlex](https://help.openalex.org/api/), [Unpaywall DOI lookup](https://data.unpaywall.org/products/api) and domain-specific [Europe PMC](https://europepmc.org/RestfulWebService) are candidates. Medium effort: identifiers, access, licenses and supplements differ. Trial: known DOIs plus ambiguous titles, correct identity/source/version and actual usable text; missing supplements remain missing. Unpaywall's search endpoint retired on 2026-09-18; its DOI lookup is a separate service. OpenAlex casual anonymous use is supported, with a daily budget; a free key increases it, and content downloads have distinct pricing. Do not assume unlimited free PDF service.

2. **Expand from a seed paper.** Follow references and later citing works to discover evidence beyond the original query. Reuse [OpenAlex](https://help.openalex.org/api/) and the already bounded OpenCitations edges route, with [OpenAIRE Graph](https://graph.openaire.eu/docs/apis/graph-api/) as a relationship candidate. Low-to-medium effort for a bounded one-hop result; a growing graph is unnecessary. Trial: find known forward/backward links in independent seed papers, retain DOI and relation; citation does not mean support and missing edges are not absence of research.

3. **Find data and code linked to research.** Return associated datasets/software, version and reuse conditions instead of only a paper. Candidates: [DataCite relationships](https://support.datacite.org/docs/connecting-to-works), OpenAIRE and existing GitHub reading. Medium effort, largely dependent on publisher/depositor registration. Trial: papers with and without registered linked resources; correct associations and explicit uncertainty, no title-only forced matching. FS03 remains the academic workflow owner.

4. **Check a report's decisive references.** Recover the actual source behind selected claims and flag a wrong identity, version or correction/retraction. Reuse [Crossref REST](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) for metadata plus existing original reading. Low-to-medium effort for selected claims; no automatic semantic truth score. Trial: known valid and intentionally mismatched references, source passages with location and unresolved claims left unresolved. Crossref metadata cannot by itself establish that a source supports the claim or that no correction exists.

5. **Read why a project changed.** Include GitHub Discussions answers, PR reviews and linked diff context. Current `search.py` public PR reader returns body plus issue comments and explicitly omits reviews/diffs; host GitHub tools already expose PR comments/patches. Prefer those to a second collector. [Discussion GraphQL](https://docs.github.com/en/graphql/guides/using-the-graphql-api-for-discussions) and [PR reviews REST](https://docs.github.com/en/rest/pulls/reviews) are official fallback mechanisms. Low effort for known PRs; medium for discussion discovery/auth. Trial: preserve answer/review state, reply chain, file/line and pagination; a closed issue or review approval does not establish a released fix.

6. **Fill community-search gaps.** Pick the community relevant to a real topic, then compare its site search with native web results. Current [OpenCLI adapters](https://github.com/jackwener/opencli/blob/main/docs/adapters/index.md) include Linux.do and other sites; [Mastodon](https://docs.joinmastodon.org/methods/search/), [Bluesky](https://docs.bsky.app/docs/api/app-bsky-feed-search-posts) and [Lemmy](https://join-lemmy.org/docs/contributors/04-api.html) expose different access mechanisms. Medium maintenance because site sessions, instance indexes and endpoint limits vary. R32's Bluesky 403 was a local result, not a permanent platform verdict. Trial: an independently relevant topic with original replies, dates, pagination and failure visibility; listed adapters are not verified integrations.

7. **Search all saved task material together.** Extend lookup to saved community posts, feed entries and subtitle segments as well as documents/reports. Current `locate` searches literal text in explicit document/report artifacts; it is not filename-only, but other artifact kinds are absent. Reuse current schemas and [SQLite FTS5](https://www.sqlite.org/fts5.html) only if ranking is useful. Low effort without a model/server. Trial: one offline query returns the right saved passage and its post URL/page/video time, including a damaged artifact; Chinese short terms need testing.

8. **Find old material when wording changes.** Add optional task-local semantic retrieval on top of the literal baseline. Compare [FastEmbed](https://qdrant.github.io/fastembed/) with small supported Chinese/multilingual models, before any Qdrant service or full QMD chain. Medium first-download/CPU cost; model and language licenses vary. R32 left QMD semantic quality unmeasured. Trial: fixed real Chinese paraphrases, cross-language requests, exact identifiers and no-answer queries, with source passages and measured first/reuse cost. Do not assume a smaller model preserves quality.

9. **Search across videos and jump to the evidence.** Reuse timestamped YouTube/Bilibili captions already retrieved by FS, then search an explicitly chosen video set offline and return source/time links. This complements the existing per-video `--find`; [yt-dlp](https://github.com/yt-dlp/yt-dlp#subtitle-options) is only a coverage candidate for other supported sites. Low effort for existing captions. Trial: cross-video hits and correct time boundaries, including absent captions. It does not require ASR; an ASR fallback would be a separately selected, heavier branch.

10. **Read scans and complex page layouts.** Use the existing installed MinerU ingest workflow if its prerequisites fit; compare [MinerU](https://github.com/opendatalab/MinerU), [OCRmyPDF](https://ocrmypdf.readthedocs.io/en/latest/installation.html) and Tesseract only for the actual failed material type. OCR text search and faithful table extraction are different outcomes. Medium-to-high dependency/model/verification cost. Trial: independent scanned and structured pages, decisive characters/cells, source-page association and preserved visual original. R32's wrong Docling cell remains a counterexample, not proof every parser fails. Licenses and Windows compatibility need candidate-specific checking before installation.

11. **Retrieve and reuse complete Deep Research reports.** Prioritize the outstanding ChatGPT local-export gap and strengthen reuse of a canonical completed session, before starting new jobs. The installed OpenCLI 1.8.7 has a [ChatGPT report extraction command](https://github.com/jackwener/opencli/blob/main/docs/adapters/browser/chatgpt.md); source presence is not local acceptance. Current [official OpenAI documentation](https://learn.chatgpt.com/docs/web-search) describes the Work Deep Research plugin, with account/workspace availability limits; this host does not currently expose a callable research-job connector. Medium browser-maintenance risk, potentially valuable for the owner's subscription preference. Trial: one existing completed report, intact ending/tables/citation URLs and offline reuse, with no duplicate submission. A rendered summary is not the original export.

12. **Explain what changed since the last investigation.** Compare selected new snapshots with saved evidence and reread only changed relevant sections. Existing Feed conditional checks, immutable reports and [changedetection.io filtering](https://github.com/dgtlmoon/changedetection.io) provide reusable mechanisms; a one-shot diff may suffice. Low-to-medium effort for fixed sources, higher for general sites. Trial: relevant factual change, navigation-only change and extraction failure yield different outcomes, while old evidence remains usable. A one-off branch selection does not authorize recurring monitoring.

13. **Add specialist source lanes.** Choose a domain first: public datasets ([DataCite](https://support.datacite.org/docs/api)), patents ([USPTO](https://data.uspto.gov/)) or regulations ([Regulations.gov](https://open.gsa.gov/api/regulationsgov/)). Medium effort and domain-specific coverage/key/metadata/access rules. Trial: known identifiers plus an unknown case, correct official record/version and original URL. A directory of APIs or a new source count is not a demonstrated improvement.

The most plausible inexpensive starts are 5, 7 and 9 because they reuse active host capabilities or existing saved artifacts. For scientific work, 1–4 form distinct selectable capabilities; they should be trialled within FS03's established division, not replace it. For the owner's earlier product interest, 11 addresses an actual unfinished gap. These are provisional priorities, not branch selection on the owner's behalf.

After selection: deepen only selected branches, fix the user outcome and acceptance before implementation, try an upstream route on one real failure and one untouched holdout, then integrate the smallest successful part. Check default cost, source location, partial failures and licensing. Publish actual outcomes; do not rename a trial as delivery. No new Goal or execution task was created for this menu.
