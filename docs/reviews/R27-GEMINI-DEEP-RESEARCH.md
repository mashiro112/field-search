# R27：从 FS 自动发起并取回 Gemini Deep Research

2026-09-17，单个真实任务的完整流程已跑通。用户明确的目标是在 Codex 调用 FS 后，由代理自动完成 Google Deep Research 并取得回答。R26 的完成报告导入只是后半段；R27 已补齐前段浏览器操作并完成启动到取回的实测。

## 路径与验收

复用已登录 Gemini 网页和现有订阅额度：选择真正的 Deep Research → 提交精简研究任务 → 核对计划并自动点击“开始研究” → 保存会话位置，低频等待同一任务完成 → 官方复制或 Docs 导出 → R26 原样保存与按需读取 → 返回回答、来源和本地报告。用户已授权研究时，计划合理即可自行启动，无需让用户再操作启动按钮。

只有实际登录验证、验证码、额度或另行收费授权等无法自动完成的节点才交接给用户。等待中不重复提交；生成研究计划不等于研究已开始，点击开始也不等于完成。只有报告实际取回、落盘并可供回答，才通过完整流程验收。

实现优先采用 Skill 的原生浏览器工作流和既有报告读取器，不另造 CLI 浏览器接口、爬虫、账户服务或后台研究平台。明确要求 Google Deep Research 时直接使用该产品；普通 FS 查询仍按实际信息缺口选择，避免每次都消耗长研究额度。

这是一次真实端到端试跑及 Home 验收；复用 R26 已独立验收的保存与分页代码，没有把历史测试当成新浏览器流程的独立验收。当前新增的是 [FS 路由与原生浏览器工作流](../../references/gemini-deep-research.md)，而非可脱离 Codex 独立运行的无头 CLI 或后台服务。

## 使用与边界

例如：“用 FS 的 Google Deep Research 调查这个问题，完成后把结论和来源给我。”调用者负责完整执行；用户已有研究授权且计划符合范围时，不重新询问是否启动。返回原问题的实质回答、关键来源和可复用报告，而不是仅返回状态或文件路径。普通 FS 请求根据实际跨度和缺口选择是否采用长研究，不无条件消耗研究额度。

本机已验证的取回路线是官方 Docs 导出和现有 Drive 连接器。Copy Contents 的完整保真度仍未实测，不要求每次重复两种导出。报告原文由 Gemini 生成，导入不等于事实或引用语义已独立核验，完整性元数据继续保留相应边界；候选推荐没有自动变成安装或开发授权。

登录验证、验证码、账户额度、意外收费或页面变动可能需要用户操作或后续维护。本次没有新增收费 API 调用，没有建立公开分享，没有复制账号凭据；不能保证所有账号、所有报告或未来界面均无需人工介入。不发布账户、会话标识、受控下载链接或原始研究正文。源码与指令清单包含此次新增参考，共 173 文件。
