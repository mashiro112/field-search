## Goal

把 Field Search 推进为一个入口即可按真实信息缺口调用成熟搜索/读取/证据找回能力的 Skill，优先消除用户为选择和部署这些工具付出的精力。本轮主动复现、比较并接入有收益的候选；结果至少保持上游在被选择场景的关键能力，并在与 FS 的衔接、可追溯、按需使用或恢复能力上证明具体改进。不能把“优于所有工具的综合”当成没有边界、无法完成的验收口号。

请用 FS01 当前的 **GPT-6 Sol** 承接此执行目标，保持当前推理设置；不要因旧工作项文档里的模型字段改回 Astra、Terra 或 Luna。延续现有 Home / Execution / Critic 职责和摘要交接方式，按任务必要性委派；Home 控制路径和漂移，Execution 做复现和实现，Critic 在结果可检验时验收。不要新增一组重复工作窗口。想法与需求窗口只收结果和必要决策，不承担持续监工。

## 要完成的探索

1. **A QMD**：对明确的任务材料集做本地混合检索。先固定版本和隔离路径，验证关键词模式，再比较语义和重排。准备中英改写、跨语言、精确版本/错误码和无答案问题；记录模型/语言局限、首次与复用成本，并保留原文位置。FastEmbed 是 QMD 不适合本机时的组件备选，不同时部署两套。不要默认扫描全局知识库或调用完整本地 LLM 链。
2. **B Crawl4AI**：复用已装运行时的有界 BFS/BestFirst/过滤能力，与当前 discover→read/batch 同题比较。先验证固定版本实际具备所需接口。限定域名、请求/页面、深度和时间，返回未访问项及失败；确认新增关键页面值不值得额外请求，不做全站抓取。
3. **C Context7**：本轮已探测到真实 docs 片段和库 ID 迁移，继续验证指定版本、原始来源和不支持版本的行为。优先现成调用，不为两个请求建立新框架。匿名访问不是长期承诺；鉴权/配额阻止时用官方版本文档/Git ref 继续任务，不索取新付费账户。
4. **D Docling**：主动找合法公开的复杂 PDF 与中文扫描样本，在同样决定性数字、表头、阅读顺序上比较 MarkItDown。复用 Docling 的结构数据，保存页/表/文本关联；本机中文 OCR 不达标时再比较 PaddleOCR，避免把“输出了 Markdown”当成保真成功。
5. **E ast-grep**：在一个真实固定提交仓库中比较结构搜索与 rg/Repomix。只读搜索，返回准确源位置；不得把压缩仓库导览当成完整实现证据。若普通检索已足够，则记录无可证明增益，不制造包装层。
6. **F faster-whisper**：用明确可使用的短音频样本复现时间戳转录，人工抽查术语、数字、否定、静音和片段边界；与字幕可用时的现有路径比较。whisper.cpp 或已有 Docling ASR 可作为有理由的替代。转录保持 ASR 身份，不静默下载整站媒体或开启付费转录。
7. **G 社区上下文**：按具体来源缺口比较当前浏览器与 OpenCLI 适配器。先读适配器和会话依赖，再做只读真实试验。成功要包含原帖、回复/后续更正及截断状态。缺登录/扩展就明确相应条件，不反复无效重试。Bluesky 匿名探测为 403，保持未接通，除非新的实际条件解决它。
8. **H SearXNG**：先检查现有本机运行条件；具备轻量隔离部署条件则直接复现少量引擎，比较同预算的独有有效来源。公共实例能打开网页不代表 JSON 可用。若需大幅改系统或新增外部服务，保留具体试验方案并继续其他分支。
9. **I 时间变化**：以两个不可变快照的一次性比较开始，借鉴 changedetection.io 的目标区域过滤。证明能区分事实变化、导航噪声及提取失败；只有缺历史快照时才尝试 Wayback。没有明确长期监控请求，不创建常驻服务/自动化。

先推进 A/B/C/D，再处理 E/F 和 G/H/I 的有界判定。此顺序是起点：允许根据证据调整，只需留下“原缺口、发现、为何改变下一步”的短说明。不把每个分支都实现当 KPI；但也不能只给一张候选清单，或因一个受阻分支中途停止其余工作。

## 复现、整合与 Critic 验收

每个准备采用的分支留一份紧凑记录：真实任务/来源、固定上游版本、现有 FS 基线、上游原生结果、接入后结果、关键证据位置、实际时间/请求/依赖成本、限制和撤回条件。固定原始材料与问题后再比较，避免读过上游答案再让基线“盲测”。若无法做独立比较，如实标为功能复现，不宣称胜出。

至少包含一个触发缺口的真实案例和一个未用来调整实现的独立案例；少量合成输入只测失败边界，不充当现实效果证据。先使用现有上游测试和 FS 检查，不搭建昂贵全量 benchmark。不得自动调用多家商业 Deep Research 或付费评委；原有登录/公开范围和 FS03 分工保持有效。

采用条件：关键内容及来源位置不丢失；接入后能从 FS 正常使用；必要错误/部分结果可见；普通简单搜索不被强制拖入新依赖。在所测场景与上游达到关键能力等价，同时给出至少一个可验证的 FS 衔接收益。没有质量增益但明显减少实际人工步骤也可采用，需量实测步骤，不能猜固定节省比例。

Critic 在有可运行结果后检查选择是否解决原问题、证据是否支持结论、默认成本是否增加以及重要反例。失败返回 Execution 修复原因，只重跑受影响验证；通过后进入下一个有价值分支。不能用更多文档和测试数量替代缺失功能，也不能为追求完美无限打磨一个边角。
