# R24：四项能力接入与集中验收

状态：实施中，尚未验收。2026-09-17 用户已同意 [ROI 建议](2026-09-17-feature-roi.md)，要求按优先级完成后一次性审阅；只有确实需要人工操作的节点才暂停依赖它的工作。

## 目标与范围

1. 视频字幕与时间定位：优先复用成熟字幕库，返回字幕类型、语言、时间与来源；失败明确。用实际公开视频核验人工/自动字幕，不自动下载媒体或付费转写。
2. Discourse 公共主题结构化读取：保留帖子、楼层、可用的回复关系和来源；显式限制读取预算并表达未读部分。两个相关公开站点验证，其中含超过首批的长主题。
3. 一次运行配置与针对性诊断：复用现有 doctor，减少重复传运行路径；显式参数保持兼容。配置只保存非敏感引用，路径有效不等于登录有效。
4. 任务内批量读取和失败续跑：复用已有读取输出；成功项不重复请求，失败项可补跑，支持显式刷新及参数隔离。以实际调用计数/记录验证，不预先宣称 token 节约比例。

这四项构成当前授权范围，不因备用项此前排序较低而跳过，也不新增 PR 阅读、向量库、通用 agent 框架或另一套科研 SOP。

## 实施与验证

沿用 `scripts/search.py` 和已有失败/快照格式；上游负责成熟读取机制，本项目只补必要适配。主入口保持简短，参数和限制按需查阅参考文件。保留回退副本，不覆盖无关改动；依赖优先隔离安装，配置和会话不进入公开仓库。

验证覆盖真实读取、受控失败、预算截断、保存后再读、配置覆盖、批量部分失败与刷新。必要检查通过后只对返修的影响范围复验；最后进行一次独立验收。真实访问失败不得改写成成功，离线样本只能验证解析和状态行为，不能替代在线验收。

单项访问障碍先查原因并尝试有依据的等价路径，同时继续其他独立项。只有人工登录、验证等无法代办的必要步骤才请求用户操作。阶段发布与代码存在均不等于最终通过；最终结果需列明实际版本、已验收行为和剩余限制。
