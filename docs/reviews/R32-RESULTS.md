# R32: mature component trials and one accepted site-search route

Date: 2026-09-23. Status: scoped delivery. This follows the [R32 goal](R32-GOAL-PROMPT.md) and the earlier [in-progress checkpoint](R32-PHASE-1.md). The current source manifest has **185** files. Raw trial outputs, local runtimes and browser/account state were not published.

## What changed

FS can now select an **X site search and reply-reading route** when an already authorized OpenCLI browser bridge works. The Skill calls upstream [`@jackwener/opencli` 1.8.7](https://github.com/jackwener/opencli) (Apache-2.0) directly; FS adds the evidence-routing and completeness boundary in [r32-x-site.md](../../references/r32-x-site.md). There is no copied adapter, paid X API, new background service or default fan-out. Ordinary web/X public-post routes remain as before.

Before: FS could discover indexed X links and read a known public post through oEmbed, but not reliably search inside X or retrieve its replies. In a real `Docling OCR` trial, OpenCLI returned five site results in 19.0 s and a selected thread's original plus two replies in 7.4 s. The existing FS public reader returned only the original post for that URL. A separate `faster whisper hallucination` trial returned five site results in 8.6 s and exactly ten requested thread posts in 8.1 s. This second query was topically loose, and ten returned posts do not establish a complete thread. Upstream source inspection found a five-cursor-page cap and no total/truncation field in the result. The FS route therefore states **reply completeness unknown**, including when fewer than the requested limit are returned. Its measurable benefit is access to in-site search and additional discussion context, not a claim of exhaustive or superior search quality.

The first trial's read-only commands and independent holdout were rerun before changing the Skill. The only new operational dependency is the already installed OpenCLI plus an authorized connected browser session for this optional route. On another host, absence of either leaves the existing public paths usable. No fixed token saving is claimed.

## Critic check and limits

The accepted G route solves the original in-site X search/reply gap in two real bounded cases, and its second thread exposes an important counterexample to the upstream “all replies” description. The Skill adds no default runtime cost; a user must have a working authorized bridge and select this route for an X-specific gap. No login or payment was initiated. Stored public evidence retains post URLs, while raw account/browser data stays local. The upstream session and X itself may change, so availability must be checked when used. A returned post is still untrusted material, not proof of its assertions.

The other eight branches are recorded as measured non-adoptions or a concrete environment block, rather than installations masquerading as accepted functionality. This round did **not** solve ChatGPT report export, FS03 academic trial, general semantic retrieval, reliable OCR or complete X-thread harvesting. Those remain separate, conditional work. No more searches or dependencies are justified by these samples alone.
