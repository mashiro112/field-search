## 验证范围

- 视频测试使用两个指定公开视频分别覆盖平台标注的人工/自动字幕；另两个输入覆盖 `TranscriptsDisabled` 和 `VideoUnavailable`。后者不是验证码或 HTTP 403 的实测证明。未下载音视频，未调用 ASR 或付费转写。
- 论坛测试为 [DiscoTOC 长主题](https://meta.discourse.org/t/discotoc-automatic-table-of-contents/111143) 与 [Python PEP 810 讨论](https://discuss.python.org/t/pep-810-explicit-lazy-imports/104131)。观测帖子流分别为 149、465 个 ID；本轮仅按预算取 25 条，保留未读状态、帖子 ID/楼层/链接和可得回复字段，不声称全文穷尽。
- 批量清单含三个完整成功项、一个无字幕失败项和一个预算导致的部分结果。第二轮复用三个成功项，第三轮强制刷新一个成功项；独立检查复用输出及尝试次数，未把运行计数换算成 token 节约比例。
- 保存文件时的字幕/论坛/批量输出为有限摘要。独立复验中四份材料的终端预览为 490–875 字符，保存对象与完整输入一致；字幕九条长匹配的预览被限制为五条、每条最多 240 字符，并保留截断标记。无 `--out` 仍可返回完整结果。
- 独立注入验证：无法判断、进程启动失败和超时均不报告登录有效或登录失效；配置传递一致，同路径配置内容变化会改变批量请求身份；空帖子流不能解释总数时标部分；已存在输出路径在发起读取前拒绝。既有显式小红书参数仍可覆盖配置。
- 结构校验通过。独立审查核对了对应源码 SHA、保存证据和回退副本；在线访问由执行端实跑，独立复验主要使用这些保存证据与受控反例，没有把回放称为又一次在线验证。

小红书的现场诊断还发现两项运行问题：新配置误指向早期未完成登录的目录，doctor 子进程缺少 Windows 浏览器运行所需的 `LOCALAPPDATA`。改用此前已经验收的授权会话引用并补传必要变量后，有界 adapter 读取返回 `ok`，doctor 报告 `session_authorized=true`。没有重新登录或扫码；成功归因于实际读取，而不是仅看到目录存在。

## 使用与限制

通过自然语言说明需要核对的视频、公开论坛主题或一组链接即可，由调用者按缺口选择相应入口；不需要用户记忆脚本参数。技术调用示例集中在 [路由说明](../../references/r24-routes.md)。

1. 视频目前限于可访问的 YouTube 字幕。没有字幕时不自动转写；时间定位只对应已返回的片段。保存后可以按需读取 JSON 查找，不存在另一个专用的离线 `video find` 子命令。
2. 论坛限定公开 Discourse JSON；帖子数预算不是整个文件的字符数上限。正文保存在文件内，超出预算仍是部分材料。
3. 批量仅支持本轮的 `read`、`video`、`discourse` 项目；只自动复用相同请求身份的 `ok`/`no_results`。`partial` 也会重读，尚不是从未读楼层继续抓取的游标恢复器。刷新选项可以主动更新旧材料。
4. 运行环境和授权会话仍保留在本机，公开仓库不包含配置内容、凭据、会话或原始账号数据。依赖与会话的持续可用性需要实际诊断，不能从一次成功永久推断。

本轮通过的是这些具体接口与失败/恢复行为；没有进行科研任务质量或 token 账单的对照实验。FS03 的真实科研任务试跑仍是独立的待完成项。
