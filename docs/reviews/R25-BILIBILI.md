# R25：Bilibili 字幕接入

2026-09-17。状态：实施与可用性验证中，尚未验收。用户要求把 Bilibili 字幕获取加入现有 FS 视频能力；R24 已验收基线保持独立。

目标是同一个 `search.py video` 入口接受 B 站链接/BV 号，正确选择分 P，返回字幕文字、时间、语言、可得的人工/AI 类型和原视频来源；沿用查找、保存后的有限预览及任务内批量复用。先验证真实访问，再实现必要适配，不加入媒体下载、ASR、合集抓取或新代理框架。

已找到 [yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py) 和 [bilibili-ai-subtitle](https://github.com/ccBilly-aipm/bilibili-ai-subtitle) 等候选。前者已有 B 站字幕实现，后者提供新版字幕元数据解析线索；需要核查当前源码、许可和本机行为后选择，不能从项目自述推断本机已成功。

关键验收边界：弹幕不算字幕；B 站 AI 轨道不能机械照搬 YouTube 的类别字段；匿名空列表可能表示登录限制或旧接口遗漏，不能一概报“没有字幕”。不运行候选工具默认的浏览器 Cookie 提取。公开路径先行；确需登录时使用明确授权的流程，避免要求用户复制凭据。

验收包括真实字幕与时间定位、分 P、语言/类型映射反例、访问失败、有限输出、B 站批量复用和一个必要的 YouTube 兼容检查。完整测试字幕和账号数据不随代码公开；后续补入所选依赖版本、实际结果、限制和最终验收。

## 匿名探测与实现初审

本机 yt-dlp 2026.08.19 对选定公开样本仅返回弹幕或空字幕；一次仅字幕下载也没有产生字幕文件。新版 `/x/v2/subtitle/web/view` 对同一公开视频的独立匿名复核返回 HTTP 200、`application/octet-stream`、2 字节空轨道响应，旧播放器接口曾给出 `need_login_subtitle=true`。另一次实施探测曾出现 AI 轨道元数据，但尚未形成稳定的字幕正文正例。因此既不能宣称已接通，也不能断言视频没有字幕。下一步是独立扫码登录后的有界验证，不再扩大匿名样本搜索。

初审发现待修复的凭据发送范围、失败被误归无字幕、语言类型映射及重复提取路径问题，已交实施合并处理。字幕 CDN 请求不应携带登录 Cookie；携凭据的 API 请求必须限制目标与重定向。当前初审不是最终验收。实现仍在变化，发布源码保持 R24 基线，待稳定的实现检查点同步。
